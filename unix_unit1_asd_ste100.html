1. Operating system (OS)

An operating system is system software. It is the interface between a user program and computer hardware. It controls shared resources. It also gives programs a consistent way to use the computer.

Diagram: the OS is the control layer
User
→
Application program
→
Operating system
→
CPU, memory, disks, devices

Memory management

The OS assigns memory to processes. It protects one process from another process.

Processor management

The OS selects the process that uses the CPU. This activity is called scheduling.

Device management

The OS controls input and output devices, such as disks, keyboards, and printers.

File management

The OS creates, stores, finds, protects, and removes files and directories.

2. Types of operating system

The same OS can have more than one capability. The categories below describe the main design goal.

Operating-system types in this unit
Batch OS
Collect similar jobs. Run them as batches. Users do not interact with each job while it runs.
Time-shared OS
Give each task a short CPU period. This period is the time quantum. It supports multitasking.
Distributed OS
Coordinate work on more than one processor or computer. The processors can have separate memory and clocks.
Network OS
Connect systems to share files, printers, applications, and management services.
Real-time OS
Respond within a required time. It is used when timing matters, for example in control systems.
Comparison chart
TypeHow it worksExample use
BatchGroups jobs before processing.Payroll and statement processing.
Time-sharedChanges the active task quickly.General multi-user UNIX and Linux use.
DistributedShares work between processors.Cooperating computer systems.
NetworkShares resources through a network.File and printer servers.
Real-timeMeets a response deadline.Robots and industrial control.

Hard and soft real-time systems

  • Hard real-time: Missing a deadline is unacceptable. A late result can cause failure.
  • Soft real-time: A late result reduces quality, but the system can continue.
Examples named in the source include FreeRTOS, VxWorks, QNX, ThreadX, and Nucleus RTOS. The source also lists UNIX, Linux, and server operating systems as time-shared examples.

3. UNIX, ANSI, and POSIX standards

UNIX began at Bell Labs in 1969. The source names Ken Thompson, Dennis Ritchie, Douglas McElroy, and Joe Ossanna. UNIX systems later developed through AT&T System V and BSD (Berkeley Software Distribution). AT&T and Sun Microsystems combined major System V and BSD work in System V Release 4.

A standard is an agreed technical specification. Standards let a developer write source code that can move between compliant systems with fewer changes. This property is called portability.

4. ANSI C standard

ANSI C made C implementations more consistent. It corrected important weaknesses in older K&R C practice. The source describes four key improvements.

4.1 Function prototypes

A prototype states a function name, return type, and parameter types. The compiler can then detect a wrong number of arguments or wrong argument types before the program runs.

unsigned long foo(char *fmt, double data);
int printf(const char *fmt, ...);  /* ... means variable arguments */
Result: A prototype can prevent invalid calls that older C compilers might accept and that might fail when the program runs.

4.2 const and volatile

QualifierMeaningTypical use
constThe program must not change the object through that name or pointer.printf(const char *fmt, ...) means printf must not modify the format string through fmt.
volatileThe value can change outside the normal program flow. The compiler must read it when the code requests a read.Memory-mapped device register or data changed by hardware.
char get_io(void) {
    volatile char *io_port = (volatile char *)0x7777;
    char ch = *io_port;  /* first hardware read */
    ch = *io_port;       /* second hardware read */
    return ch;
}

Without volatile, an optimizer can treat two reads as the same read. This is unsafe when hardware can change the value between reads.

4.3 Wide characters and internationalization

ANSI C supports wide characters. A wide character can use more than one byte. The setlocale function selects regional formats, such as date, money, and number formats.

#include <locale.h>
char *setlocale(int category, const char *locale);

For example, many places use dd/mm/yyyy. The United States often uses mm/dd/yyyy.

4.4 Function pointers

A function pointer stores the address of a function. ANSI C allows a function call through the pointer without an explicit * dereference.

extern void foo(double value, const int *ptr);
void (*funptr)(double, const int *) = foo;

foo(12.78, numbers);       /* direct call */
funptr(12.78, numbers);    /* call through pointer */

Older K&R C style also allowed (*funptr)(...). The term dereference means use the pointer to access the function that it identifies.

4.5 Preprocessor symbols

The C preprocessor assigns values to predefined symbols during compilation.

SymbolUse
__STDC__Feature test for ANSI C conformance. Historical notes may show _STDC_; modern compilers use __STDC__.
__LINE__Line number of the source reference.
__FILE__Name of the source file.
__DATE__Compilation date.
__TIME__Compilation time.
#include <stdio.h>
int main(void) {
#if __STDC__
    printf("%s compiled at %s %s; line %d\n",
           __FILE__, __DATE__, __TIME__, __LINE__);
#endif
    return 0;
}

ANSI/ISO C++

The source says an ANSI/ISO C++ compiler supports classes, derived classes, virtual functions, operator overloading, templates, exceptions, and iostream library classes. These are C++ language features, not ANSI C features.

5. POSIX standards and environment

POSIX means Portable Operating System Interface. IEEE specifies this family of API standards. POSIX began from UNIX practice, but a POSIX-compliant system does not have to be a UNIX system.

PartMain purpose stated in the sourceHistoric identifier
POSIX.1Base OS API. Includes file and process manipulation.IEEE 1003.1-1990; ISO/IEC 9945-1:1990
POSIX.1bReal-time interfaces, including inter-process communication (IPC).IEEE 1003.4-1993
POSIX.1cMultithreaded programming interface.Thread extension in the course material

The source gives VMS, OS/2, and Windows NT as examples of systems that can support POSIX even when they are not UNIX systems.

Requesting POSIX declarations

In old source examples, define a feature-selection macro before you include any system header. The course notes show _POSIX_SOURCE and _POSIX_C_SOURCE 199309L. Modern programs normally use a current value that the target system supports.

/* Put this before any system header. */
#define _POSIX_C_SOURCE 200809L
#include <unistd.h>

Or pass a definition to the compiler, for example cc -D_POSIX_C_SOURCE=200809L program.c.

Header files and libraries

UNIX commonly stores C and C++ headers under /usr/include. A program includes a header with #include <header-name>. POSIX defines the interface; it does not require the header to exist at one fixed physical path. Common POSIX and UNIX declarations are in <unistd.h>. Many API implementations are supplied by the C library, such as libc.

POSIX feature-test macros

Feature-test macros tell a program whether an optional capability exists. The source says these macros are in <unistd.h>.

MacroMeaning in the source
_POSIX_JOB_CONTROLThe system supports BSD-style job control.
_POSIX_SAVED_IDSA process has saved set-user-ID and set-group-ID values. It can set effective IDs to those saved values through related APIs.
_POSIX_CHOWN_RESTRICTEDControls whether ordinary users can change ownership of their files. A value of -1 has the course meaning stated in the source.
_POSIX_NO_TRUNCDescribes handling of a pathname that is longer than NAME_MAX.
_POSIX_VDISABLEDescribes the special-character disable value for terminal files.
#include <stdio.h>
#include <unistd.h>
int main(void) {
#ifdef _POSIX_JOB_CONTROL
    puts("System supports job control.");
#else
    puts("System does not support job control.");
#endif
    return 0;
}

7. Compile-time and run-time limits

A limit is a boundary that the system supports. POSIX defines minimum values for some limits. Programs can check limits at compile time or at run time.

Compile time

Use constants in <limits.h>. The values are available while the program is compiled.

Run time

Call sysconf, pathconf, or fpathconf. The return value can depend on the running system or a file object.

int main(void) {

    if (value == -1) perror("sysconf");
    else printf("OPEN_MAX: %ld\n", value);

    if (value == -1) perror("pathconf");
    else printf("Maximum path length: %ld\n", value + 1);
    return 0;
}

FIPS requirement in the source

FIPS means Federal Information Processing Standard. The source describes its POSIX.1 profile as more restrictive. It requires job control, saved IDs, defined _POSIX_CHOWN_RESTRICTED and _POSIX_VDISABLE, at least 8 for NGROUP_MAX, specified interrupted read/write behavior, and group-ID inheritance for a new file. It also says long path names are not supported in this profile.

8. API return values and errors

Many APIs return an integer status. In the course pattern, -1 means that the API failed. The API sets the global errno value to an error code. Error codes are declared in <errno.h>.

Diagram: normal error-handling sequence
Call API
→
Check return value
→
If -1, read errno
→
Show or handle the error
#include <stdio.h>
#include <errno.h>
#include <string.h>

/* After an API reports failure: */
perror("open");                 /* prints a standard diagnostic */
fprintf(stderr, "%s\n", strerror(errno)); /* gets error text */

perror prints a diagnostic message. strerror(errno) returns a message string. A program can print that string in its own format.

9. Fast exam revision

  • An OS manages memory, CPU scheduling, devices, and files.
  • Time sharing uses short CPU periods called quanta.
  • Hard real-time work cannot miss its deadline. Soft real-time work can tolerate some delay.
  • ANSI C improved C with prototypes, qualifiers, wide-character support, and simpler function-pointer calls.
  • const prevents modification through a name. volatile protects required reads from compiler optimization.
  • POSIX defines portable APIs. A POSIX system does not have to be UNIX.
  • <unistd.h> contains many POSIX and UNIX declarations.
  • Use sysconf for system values; use pathconf or fpathconf for file-object values.
  • For many APIs, -1 signals failure and errno explains the reason.
