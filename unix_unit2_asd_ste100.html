1. Files and file types

Files are building blocks of UNIX. When you run a command, the system finds its executable file and loads its instructions into memory. File management is a main operating-system function.

UNIX file types
Regular file
Stores program or user data.
Directory
Maps names to files and subdirectories.
Device file
Represents a hardware device.
FIFO
A named pipe for processes.
Link
Another name or a path reference.
Socket
Communication endpoint.

Regular files

A regular file can store text or binary data. UNIX APIs treat both as byte sequences. Permissions decide who can read, write, or execute it. Editors and compilers can create regular files. Use rm file to remove a directory entry.

Directories

A directory organizes names in a hierarchy. Every directory includes . for itself and .. for its parent. Use mkdir path to create one. Use rmdir path to remove an empty one.

Device files

TypeTransfer methodExamples in the PDF
Block deviceTransfers data in blocks.Hard disk and floppy disk.
Character deviceTransfers a byte stream.Terminal, modem, and printer.

Programs can commonly use read and write on device files as they do on regular files. The major number selects a device driver. The minor number identifies the device instance or its mode.

The PDF shows mknod /dev/cdsk c 115 5. Modern systems normally create device nodes automatically. Do not create or change /dev entries unless you administer the system.

FIFOs (named pipes)

A FIFO is a special pipe that has a file-system name. Processes exchange data through a temporary kernel buffer. The buffer exists while processes keep the FIFO open. The source specifies PIPE_BUF as its buffer size.

mkfifo /usr/prog/fifo_pipe
# Historical alternative: mknod /usr/prog/fifo_pipe p

A FIFO directory entry can be removed like a regular-file entry. Its data is not permanent.

Symbolic links

A symbolic link stores a pathname for another file. It can refer to a local or remote-mounted file system. Create it with ln -s target linkname.

3. Inodes, directories, and names

An inode is a record for a file. It stores metadata and the location of file data on disk. An inode number is unique only inside one file system. A file is identified by its file-system ID and inode number.

Important: An inode does not store a file name. A directory maps a name to an inode number.
Diagram: resolving /usr/abc
Root inode
find “usr”
inode for /usr
find “abc”
inode for abc
→
metadata and data blocks

The kernel checks the calling process permissions during this lookup.

struct stat

struct stat, declared in <sys/stat.h>, holds file attributes returned by metadata APIs.

struct stat {
    dev_t st_dev; ino_t st_ino; mode_t st_mode; nlink_t st_nlink;
    uid_t st_uid; gid_t st_gid; dev_t st_rdev; off_t st_size;
    time_t st_atime; time_t st_mtime; time_t st_ctime;
};

These members represent the file-system ID, inode, type/mode, hard-link count, owner IDs, device ID, size, and relevant timestamps.

4. Kernel support for open files

Each process has its own file descriptor table. It maps a small integer, such as 3, to a system-wide open-file entry. The PDF states that the table can have up to OPEN_MAX entries.

Diagram: three file-access levels

fd 0, 1, 2, 3...
points to
System-wide open-file table
mode, flags, offset, reference count
points to
Inode table
metadata and disk blocks
StructureScopeStores
Descriptor tablePer processDescriptor flags, including close-on-exec, and an open-file pointer.
Open-file tableSystem-wideMode, flags, current offset, reference count, and inode pointer.
Inode tableSystem-wide or file-system scopeFile metadata and data location.

If a process opens log.txt twice, it usually gets two descriptors and two open-file entries. They can have different modes and offsets. Another process can still point to the same inode.

What open does

  1. Resolve the pathname to an inode and check permission.
  2. Find the first unused descriptor entry for the process.
  3. Find an unused system-wide open-file entry.
  4. Connect descriptor → open-file entry → inode.
  5. Set mode, current offset, and reference count.

If the inode does not exist, or permission is missing, open returns -1.

System call and API

A system call is a defined request to the kernel. An API is the wider interface contract that tells software components how to interact. Some APIs are thin wrappers around system calls.

5. Hard links and symbolic links

A hard link is another directory entry for the same inode. A symbolic link is a separate small file that stores a target path.

Hard linkSymbolic link
Uses the target inode. It does not create a new target inode.Has its own inode for the link file.
Increases target hard-link count.Does not change target hard-link count.
Normally cannot link directories.Can name directories.
Cannot cross file-system boundaries.Can cross file systems.
Still works after one other hard-link name is removed.Can become broken when its target moves or is removed.
# Create a hard link.
ln /usr/satish/old.c /usr/ravi/new.c

# Create a symbolic link.
ln -s /usr/satish/old.c /usr/ravi/new.c

cp creates a separate copied file. ln saves data space because it creates a name, not another copy. UNIX normally disallows hard links to directories because they can create cycles.

6. Opening files and permissions

open connects a process to a file. It returns a file descriptor for read, write, and close.

#include <fcntl.h>
int open(const char *pathname, int flags, ...);

The third argument is needed only with O_CREAT. It gives requested creation permissions.

Access flagMeaning
O_RDONLYOpen an existing file for reading only.
O_WRONLYOpen for writing only.
O_RDWROpen for reading and writing.
ModifierMeaning
O_APPENDWrite at the end of the file.
O_CREATCreate if the path does not exist.
O_EXCLWith O_CREAT, fail if it exists.
O_TRUNCSet existing file size to zero when allowed.
O_NONBLOCKRequest non-blocking operation for suitable types.
O_NOCTTYDo not make a terminal the controlling terminal.
O_SYNCWait for required physical I/O completion.
int fd = open("/etc/passwd", O_RDONLY);
int out = open("foo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);

Permissions

Each file has owner, group, and other categories. Each can have read, write, and execute access. Read = 4, write = 2, execute = 1.

DigitPermissions
7rwx (4 + 2 + 1)
6rw-
5r-x
4r--
0---

755 means owner rwx, group r-x, and other r-x. 644 means owner rw-, group r--, and other r--. For a directory, execute means search or traverse.

umask removes permissions from a requested creation mode. Example: requested 0666 with umask 0022 usually results in 0644.

7. Read, write, close, fcntl, and lseek

read

#include <unistd.h>
ssize_t read(int fd, void *buf, size_t count);

read attempts to copy up to count bytes into buf. It returns bytes read, 0 at end of a regular file, or -1 on error. A FIFO or device can block until data is ready. Non-blocking mode can change this behavior.

write

ssize_t write(int fd, const void *buf, size_t count);

write attempts to copy bytes from buf to an open file. It returns the bytes written or -1 on error, such as no space. A short write is possible, so robust programs handle it.

close

int close(int fd);

close disconnects a descriptor and releases resources when no references remain. The kernel closes open descriptors when a process ends. It returns 0 on success and -1 on failure.

fcntl

#include <fcntl.h>
int fcntl(int fd, int cmd, ...);
CommandUse
F_GETFLGet file status flags.
F_SETFLSet permitted file status flags, such as append or non-blocking.
F_GETFDGet descriptor flags, including close-on-exec.
F_SETFDSet or clear descriptor flags.
F_DUPFDDuplicate a descriptor.

lseek

off_t lseek(int fd, off_t offset, int whence);

lseek changes the current file offset and supports random access on seekable files. It does not apply meaningfully to FIFOs, sockets, or many character devices.

whenceReference
SEEK_SETStart of file.
SEEK_CURCurrent offset.
SEEK_ENDEnd of file.
lseek(fd, 10, SEEK_CUR);   /* move forward 10 bytes */
lseek(fd, -10, SEEK_END); /* 10 bytes before end */

8. Links and metadata APIs

link and unlink

int link(const char *existing, const char *newname);
int unlink(const char *pathname);

link creates a new hard-link name and increases the hard-link count. unlink removes one name and decreases the count. The data is removed only when the count is zero and no process has the file open.

stat, fstat, and lstat

int stat(const char *path, struct stat *st);
int fstat(int fd, struct stat *st);
int lstat(const char *path, struct stat *st);

stat gets attributes from a path. fstat gets them from an open descriptor. stat follows a symbolic link. lstat gets attributes of the link itself. These calls return 0 on success and -1 on failure.

Change permissions and ownership

int chmod(const char *path, mode_t mode);
int fchmod(int fd, mode_t mode);
int chown(const char *path, uid_t uid, gid_t gid);
int fchown(int fd, uid_t uid, gid_t gid);
int lchown(const char *path, uid_t uid, gid_t gid);

chmod and fchmod change mode bits. chown and fchown change target-file owner or group. lchown changes a symbolic link itself. A uid or gid value of -1 means do not change it.

Other APIPurpose

9. File and record locking

Multiple processes can read and write one regular file. Locking coordinates access. File locking applies to regular files.

LockOther readersOther writersPurpose
Read / sharedAllowedNot allowed on overlapping regionPermit readers and stop writers.
Write / exclusiveNot allowed on overlapNot allowed on overlapProtect data while it changes.

Mandatory and advisory locks

Mandatory

The kernel enforces the lock for normal I/O. A runaway process can block other access until it stops or the system restarts.

Advisory

The kernel records the lock, but programs must cooperate. Acquire lock, access data, then release it promptly.

fcntl locking commands

CommandUse
F_SETLKSet or clear a lock. Do not block if it cannot succeed.
F_SETLKWSet or clear a lock. Wait until it can succeed.
F_GETLKQuery a conflicting lock and its owner.
struct flock {
    short l_type;    /* F_RDLCK, F_WRLCK, F_UNLCK */
    short l_whence;  /* SEEK_SET, SEEK_CUR, SEEK_END */
    off_t l_start;   /* start position */
    off_t l_len;     /* length; 0 means to end */
    pid_t l_pid;     /* owner from F_GETLK */
};

l_start is measured from l_whence. l_len gives the region size. A length of 0 extends to the current or future end of the file. Changing a read lock to a write lock is lock promotion. Unlocking a middle section can split one lock into two.

The PDF says mandatory locking can be requested by setting set-GID and clearing group execute. This is platform-specific and usually discouraged. Locks held by a process are released when that process ends. The PDF states that a child created by fork does not inherit its parent locks.

10. Revision and practice

  • A file descriptor is a per-process integer handle for an open file.
  • An open-file entry stores mode, flags, offset, reference count, and inode pointer.
  • An inode stores metadata, not a file name.
  • A directory maps names to inode numbers.
  • Hard links share an inode. Symbolic links store a path.
  • open returns a descriptor; read, write, and close use it.
  • stat follows links; lstat reads a link itself.
  • Read locks are shared. Write locks are exclusive.
  • Use F_SETLK for a non-blocking lock attempt and F_SETLKW to wait.
